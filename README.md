# GroceryMate

An offline-first grocery shopping assistant built with Flutter. The app helps
people organise grocery lists, maintain a product catalog, add products by
manual entry or barcode text, track estimated costs and budgets, compare store
prices, and review spending history. No account or internet connection is
needed for core features.

> Grocery List Management (create, edit, delete, status changes, categories,
> filtering, and sorting) is backed by local SQLite persistence. The Grocery
> Lists screen has a collapsible category section and swipe status transitions
> with brief Undo. The new Product Catalog (Milestone 5A) is also local-first:
> create/edit products, custom categories, search/filter/sort, duplicate-name
> warnings, unique barcode enforcement, and archive/restore are available
> offline. Grocery item CRUD and the remaining feature areas remain later
> milestones.

The structure stays feature-first. Widgets never import Drift: they talk to
`GroceryListController` or `ProductController`, both `ChangeNotifier`s. When a
repository is injected, each controller subscribes to its watch streams and
delegates mutations to it. Without a repository it uses the same in-memory data
path as before, which keeps focused widget tests lightweight.

## Product Catalog (Milestone 5A)

The Product Catalog is reachable from the shared navigation drawer. It provides:

- Active product list with search by **name or brand**, horizontal **category
  filter** chips, and sorting by **Name (A-Z)**, **Recently added**, or
  **Recently updated**.
- Empty states for no catalog data, no archived products, and no search/filter
  results.
- An archive toggle in the app bar. Archived products have their own view and
  are hidden from active searches and selection. Restore is available from the
  product card menu; nothing is permanently deleted in this milestone.
- A reusable create/edit bottom sheet with required name, required product
  category, required default unit, and optional brand, barcode, local image
  path, and notes.
- Eleven units: Piece, Kilogram, Gram, Liter, Milliliter, Pack, Box, Bottle,
  Can, Dozen, and Bundle.
- Ten predefined product categories (**Produce**, **Dairy & Eggs**,
  **Meat & Seafood**, **Bakery**, **Pantry**, **Frozen Foods**, **Beverages**,
  **Household**, **Personal Care**, **Other**) plus user-created categories.
  These are independent of Grocery List categories.
- Similar-name warnings with **Open existing product** and **Create separate
  product** paths. Product names are never forced to be unique.
- Barcode uniqueness enforcement. Spaces and hyphens are ignored when comparing
  barcodes, and an existing barcode can never be silently assigned to another
  product.

`AppDestination.productPrices` remains a separate placeholder for future price
work; Product Catalog has its own destination and route
(`/product-catalog`).

## Persistence architecture

### Initialization and database location

`main()` calls `WidgetsFlutterBinding.ensureInitialized()`, constructs
`AppDatabase`, wraps it in `DriftGroceryListRepository` and
`DriftProductRepository`, and passes both repositories through
`GroceryScanApp` → `AppRoutes` → the relevant screen.

`AppDatabase` uses `driftDatabase(name: 'grocery_mate')` from
`package:drift_flutter`:

- **Android / iOS / desktop:** `grocery_mate.sqlite` in the application
  documents directory, opened in a background isolate.
- **Web:** IndexedDB/OPFS via the bundled `web/drift_worker.js` and
  `web/sqlite3.wasm` assets from the Drift 2.35.4 release. For best web
  performance, serve WASM as `application/wasm` and consider the
  `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: require-corp` headers.

No explicit `path_provider` dependency was added; `drift_flutter` brings the
platform plumbing transitively.

`MigrationStrategy` runs `createAll()` on database creation, enables SQLite
foreign keys in `beforeOpen`, and seeds starter data in transactions.
`schemaVersion` is now `2`. The `1 → 2` upgrade creates only the new product
tables and their indexes, then seeds product categories. No grocery table is
altered, dropped, or reseeded.

### Tables

| Table | Columns | Constraints / indexes |
| --- | --- | --- |
| `categories` | `id` TEXT UUID PK, `name` TEXT, `is_system` BOOLEAN, `sort_order` INTEGER, `created_at` DATETIME | Non-empty name; unique on `lower(trim(name))` via generated SQL index |
| `grocery_lists` | `id` TEXT UUID PK, `name` TEXT, `category_id` TEXT NULL, `budget` INTEGER NULL, `status` TEXT, `created_at` DATETIME, `updated_at` DATETIME | `category_id` FK → `categories(id)` `ON DELETE SET NULL`; non-empty name; status in `active/completed/archived`; non-negative budget; indexes on category, status, and updated time |
| `grocery_list_items` | `id` TEXT UUID PK, `grocery_list_id` TEXT, `item_name` TEXT, `quantity_milli` INTEGER, `unit` TEXT NULL, `estimated_unit_price` INTEGER NULL, `notes` TEXT NULL, `is_checked` BOOLEAN, `sort_order` INTEGER, `created_at` DATETIME, `updated_at` DATETIME | `grocery_list_id` FK → `grocery_lists(id)` `ON DELETE CASCADE`; non-empty item name; `quantity_milli > 0`; non-negative estimated price; index on `grocery_list_id` |
| `product_categories` | `id` TEXT UUID PK, `name` TEXT, `is_predefined` BOOLEAN, `sort_order` INTEGER, `created_at` DATETIME, `updated_at` DATETIME | Non-empty name; unique on `lower(trim(name))` via generated SQL index |
| `products` | `id` TEXT UUID PK, `name` TEXT, `category_id` TEXT, `unit` TEXT, `brand` TEXT NULL, `image_path` TEXT NULL, `notes` TEXT NULL, `is_archived` BOOLEAN, `created_at` DATETIME, `updated_at` DATETIME | `category_id` FK → `product_categories(id)` `ON DELETE RESTRICT`; non-empty name; unit must be one of the 11 predefined values; indexes on category, archived flag, name, created time, and updated time. Product names are intentionally **not unique**. |
| `product_barcodes` | `id` TEXT UUID PK, `product_id` TEXT, `value` TEXT, `created_at` DATETIME | `product_id` FK → `products(id)` `ON DELETE CASCADE`; non-empty value; unique index on `value`; unique index on `product_id` (one barcode per product) |

The `grocery_list_items` table is still a schema placeholder for a later
feature; this milestone adds no grocery item CRUD or UI.

### Data conventions

- Primary keys are UUID v4 strings, generated by `IdGenerator` without another
  package. Seeded categories and sample lists use fixed UUIDs.
- All grocery money is stored as integer centavos. `GroceryListInput` converts
  peso values to/from centavos and rejects negative, non-finite, or blank input.
- `DateTime` values are stored as ISO-8601 UTC text (`build.yaml`), then mapped
  to local `DateTime` objects at the repository boundary for display.
- `GroceryListStatusConverter` maps the enum to readable TEXT values.
- Multi-record writes (seeding, list + new category creation, list edits,
  product + barcode writes) run inside transactions. Foreign keys are enabled
  on every connection.
- Row classes stay inside `core/database` and `data`; the UI uses domain
  objects only.
- Product image support stores only a local path string in `products.image_path`.
  There is no image picker, camera capture, or cloud upload in this milestone.

### First-run seeding

On a brand-new database only, a transaction inserts the six predefined grocery
categories (`Weekly`, `Monthly`, `Personal`, `Family`, `Party`, `Other`) and
five sample lists. IDs and timestamps are fixed, so seeding is deterministic.
On later launches the grocery seeder sees existing categories and does nothing:
deleted samples are never reinserted, and user edits are never overwritten.

The ten predefined product categories are seeded only during database creation
or the `1 → 2` upgrade. They are not re-created, renamed, or restored on normal
launches, so deleted or edited product categories stay that way.

## Manual Android testing

1. Run `flutter devices`, then `flutter run -d <android-device-id>` on a physical
   device or emulator.
2. On the Grocery Lists screen, confirm existing lists/categories still appear.
   Open the menu and choose **Product Catalog**.
3. Tap **+**. Verify name, category, and unit are required. Enter a product with
   a brand, barcode, local image path, and notes; optionally create a custom
   category; then save. Confirm the product appears in the active list.
4. Search by product name and by brand. Switch category chips and the sort menu;
   verify the list updates.
5. Add a product with a similar name. Confirm the warning appears and both
   **Open existing product** and saving a separate product work.
6. Try to save another product with the same barcode. Confirm the inline barcode
   error blocks the save; change the barcode and confirm it saves.
7. From a product card menu, choose **Archive**. Confirm it disappears from the
   active list, appears under the archive toggle, and can be restored.
8. Force-stop and reopen the app. Confirm products, custom categories, archive
   state, and Grocery Lists data all persist.
9. Optional upgrade check: install a build with schema v1, create a grocery list,
   then install this build over it. Confirm the grocery list is intact, the
   product catalog tables exist, and the ten product categories appear once.
